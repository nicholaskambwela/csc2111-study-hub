CSC 2111 · Topic 03

Designing for Performance

// pipelining · superscalar · multicore · Amdahl's Law · cache trade-offs

// 01

Performance Balance

The CPU keeps getting faster — but RAM hasn't kept up. This creates a processor-memory gap: the CPU sits idle waiting for data it needs. This is the core problem "Designing for Performance" addresses.

🧠

Processor Speed

Roughly doubles every 18 months (Moore's Law). Modern CPUs run at 3–5 GHz.

💾

Memory Speed

DRAM speed improves much more slowly — creating a widening gap with CPU speed.

⚠️

The Problem

CPU stalls waiting for memory. A fast processor doing nothing is a waste of silicon.

🛠️

The Solutions

Cache, pipelining, superscalar, branch prediction, multicore — all address this gap.

📋
Exam Tip: "Describe three strategies to address the processor-memory gap" is a common question. Answers: cache memory, pipelining / out-of-order execution, and prefetching.
// 02

Pipeline Hazards:

🏗️

Structural Hazard

Two instructions need the same resource simultaneously. Fix: duplicate resources or stall.

📊

Data Hazard

Instruction needs result not yet written. Fix: forwarding/bypassing.

🔀

Control Hazard

Branch — CPU doesn't know what's next. Fix: branch prediction.

Pipelining Speedup: Speedup = Non-pipelined time / Pipelined time = (CPI_old × clock_old) / (CPI_new × clock_new)
// 03

Superscalar Execution

Pipelining gets CPI close to 1. Superscalar breaks through that barrier — issuing multiple instructions per clock cycle using multiple execution units in parallel.

FeaturePipeliningSuperscalar
ConceptOverlap stages of one streamExecute multiple instructions simultaneously
Execution unitsOne pipelineMultiple ALUs, FPUs, load/store units
Ideal CPI≈ 1< 1 (e.g., 0.5 with issue width 2)
DisadvantageHazards cause stallsComplex hardware, dependency checking
Examiners love this distinction: Pipelining overlaps stages of different instructions. Superscalar executes multiple instructions at the same stage simultaneously. Both work together in modern CPUs.
// 04

Branch Prediction & Speculative Execution

When the CPU hits a branch (if/else, loop), it doesn't know which path to take until the condition is evaluated. Waiting wastes pipeline cycles.

🎯

Branch Prediction

CPU guesses which branch will be taken using historical patterns. Modern CPUs are right ~95% of the time.

🚀

Speculative Execution

CPU starts executing the predicted path before knowing if the guess is correct. If right — no stall. If wrong — rollback.

💥

Misprediction Cost

Wrong guess = flush pipeline, discard work, restart. Can cost 10–20 wasted cycles.

Why it works: With ~95% accuracy, the pipeline almost never stalls on branches. The CPU is nearly always already working on the right instructions before it even knows for sure.
// 05

Multicore & The Clock Speed Wall

From the 1970s to early 2000s, clock speed was the primary way to improve performance. Then it hit a wall.

🔥

Power Wall

Higher clock speed = more power = more heat. Chips were becoming physically impossible to cool.

⚡

The Pivot (~2005)

Instead of one fast core, use multiple slower cores. Same transistor budget, parallel work instead.

🖥️

Multicore vs MIC vs GPGPU

Multicore: few powerful cores. MIC: dozens of simpler cores. GPGPU: thousands of tiny cores for parallel workloads.

⚠️

Cache Trade-off

More cores = less cache per core. More cache = fewer cores. Every chip is a balancing act.

// 06

Amdahl's Law

Amdahl's Law gives you the theoretical maximum speedup from parallelism — and explains why throwing more cores at a problem eventually stops helping.

AMDAHL'S LAW
Speedup = 1 / ( (1 − f) + f/N )
f = parallelizable fraction of the program
N = number of processors
(1 − f) = serial portion — this is the bottleneck
Maximum speedup (N→∞) = 1 / (1 − f)
The brutal truth: If 35% of your program is serial, max speedup = 1/0.35 = 2.86× — regardless of how many processors you use. The serial portion is always the ceiling.

🔥 Multiple Choice Quiz

Q1. Why did the industry shift from increasing clock speed to multicore processors in the 2000s?

✅ Power wall! Higher clock = exponentially more heat. Chips were becoming physically impossible to cool. Multicore was the answer — same transistor budget, parallel work instead of raw speed.

Q2. Which correctly distinguishes pipelining from superscalar execution?

✅ Correct! Pipelining = assembly line (overlap stages). Superscalar = multiple assembly lines (CPI < 1 possible). They complement each other in modern CPUs.

Q3. A program is 80% parallelizable. What is the maximum speedup regardless of processor count?

✅ 5×! Max speedup = 1/(1−f) = 1/0.2 = 5. The serial 20% is the hard ceiling — no number of processors gets past it.

Q4. Which pipeline hazard does branch prediction solve?

✅ Control hazard! Branches create control hazards — the CPU doesn't know which instruction is next. Branch prediction guesses so the pipeline keeps flowing without stalling.

📖 Theory Questions — Reveal Style

Lesson 5 · Stallings Ch.26 marks
Explain the need for performance balance. Describe three strategies to address the processor-memory interface gap.
▶ Model Answer Need: CPU speed has improved far faster than DRAM speed, creating a bottleneck where the CPU stalls waiting for memory. A fast processor doing nothing wastes its potential.

Three strategies:
1. Cache memory — fast storage close to the CPU reduces trips to slow main memory.
2. Pipelining / out-of-order execution — CPU works on other instructions while waiting for a memory access to complete.
3. Prefetching — CPU predicts what data is needed next and loads it into cache before it's requested, hiding latency.
2025 Final Exam Style10 marks
Explain the three types of pipeline hazards. For each, give a brief example and one solution used in modern processors.
▶ Model Answer 1. Structural Hazard: Two instructions need the same hardware resource simultaneously. Example: two instructions both need the memory bus. Solution: duplicate resources (separate instruction/data caches) or pipeline stall.

2. Data Hazard: An instruction needs a result from a previous instruction not yet written. Example: ADD R1,R2,R3 immediately followed by SUB R4,R1,R5 — R1 isn't ready. Solution: forwarding/bypassing — route result directly without waiting for write-back.

3. Control Hazard: A branch means the CPU doesn't know which instruction comes next. Example: an if-statement. Solution: branch prediction — guess the path and speculatively execute. Rollback if wrong.
Lesson 5 · Common Final6 marks
Distinguish between pipelining and superscalar execution. Give one advantage and one disadvantage of each.
▶ Model Answer Pipelining: Divides instruction execution into stages; different instructions occupy different stages simultaneously.
✓ Increases throughput without increasing clock speed.
✗ Hazards cause stalls that reduce efficiency.

Superscalar: Issues multiple instructions per clock cycle using multiple execution units.
✓ Can achieve CPI < 1 — dramatically higher throughput.
✗ Complex hardware needed to detect dependencies. Higher power consumption.
Lesson 5 · Multicore10 marks
Why does adding more cores not always give linear speedup? Discuss hardware and software issues. Mention Amdahl's Law.
▶ Model Answer Hardware issues: Cache contention (cores compete for shared cache), memory bandwidth bottleneck (all cores share one memory bus), synchronization overhead (locks cause waiting), increased power consumption.

Software issues: Not all programs are parallelizable — serial sections limit speedup. Thread synchronization bugs (race conditions, deadlocks). Uneven load balancing leaves some cores idle.

Amdahl's Law: Speedup = 1/((1−f) + f/N). The serial fraction (1−f) is the hard ceiling. If 30% is serial, max speedup = 1/0.3 = 3.33× regardless of N. More cores give diminishing returns as the serial portion dominates.
