Memory Hierarchy

The Speed-Cost Problem

Fast memory is expensive. Cheap memory is slow. The CPU can execute billions of operations per second — main memory takes ~100ns to respond. That gap would make the CPU sit idle 99% of the time. The solution: layers.

LevelTypeSizeSpeedCost
RegistersSRAMBytes~0.3nsHighest
Cache (L1/L2/L3)SRAMKB–MB1–10nsHigh
Main MemoryDRAMGB~100nsMedium
Secondary StorageHDD/SSDTBms rangeLow

Locality of Reference — Why Cache Works

Temporal locality: If you accessed a memory location recently, you'll probably access it again soon. (Think: loop variables.)

Spatial locality: If you accessed address X, you'll probably access X+1, X+2 soon. (Think: arrays, sequential code.)

Cache works because programs don't access memory randomly — they cluster around the same locations. A tiny cache covering the "hot" data gives massive performance gains.

// 02 · concept

How Cache Improves Performance

Hit vs Miss

When the CPU needs data, it checks cache first. Cache hit — data is there, fast access. Cache miss — data not there, go to main memory (slow), bring the block into cache.

Hit Ratio (h) = Number of cache hits / Total memory accesses

Average Access Time (Tavg) = h × Tcache + (1−h) × Tmain

Example: h=0.9, T_cache=10ns, T_main=200ns → T_avg = 0.9×10 + 0.1×200 = 29ns (vs 200ns without cache!)

Four Methods of Accessing Memory (Exam Q: 8 marks)

1. Sequential access — data accessed in a fixed, linear sequence (magnetic tape).

2. Direct access — move to a region, then sequential within that region (HDD).

3. Random access — any address accessible in equal time (RAM, cache).

4. Associative access — content-addressed, no address needed — match data by value (CAM, cache tags).

Cache Mapping Techniques

Exam fact: This appears in EVERY final exam. Know all three techniques and be able to compute address divisions for each.

1. Direct Mapped

Each main memory block maps to exactly one cache line. Simple, fast, but causes conflict misses — two popular blocks can't coexist if they map to the same line.

Cache Line = Block Address mod Number of Cache Lines

Address = [ Tag | Line | Word ]

// Direct Mapped — block 5 with 4 cache lines: Block 0 → Line 0 (0 mod 4) Block 1 → Line 1 (1 mod 4) Block 4 → Line 0 (4 mod 4) ← CONFLICTS with Block 0! Block 5 → Line 1 (5 mod 4)

2. Fully Associative

A block can go into any cache line. No conflict misses. But checking all lines simultaneously needs complex, expensive hardware (comparators for every line).

Address = [ Tag | Word ]

No Line field — because the block can be anywhere, you compare tag against ALL cache lines at once.

3. Set-Associative (The Best of Both) ★ Most Tested

Cache lines are grouped into sets. A block maps to a specific set (like direct-mapped) but can go into any line within that set (like fully associative). A k-way set-associative cache has k lines per set.

Number of Sets = Total Cache Lines / k (associativity)

Set Number = Block Address mod Number of Sets

Address = [ Tag | Set | Word ]

// 4-way set-associative, 32 lines → 32/4 = 8 sets Block 0 → Set 0 (0 mod 8), any of 4 lines in set 0 Block 8 → Set 0 (8 mod 8), any of 4 lines — no conflict! Block 13 → Set 5 (13 mod 8)
FeatureDirect MappedSet-AssociativeFully Associative
Hardware complexityLowMediumHigh
Conflict missesHighMediumNone
Hit ratioLowerBetterBest
Lookup speedFastestFastSlowest
Used in practiceSome L1Most commonRare (TLBs)
Why is the tag stored in cache? Because multiple blocks can map to the same cache line (in direct/set-associative). The tag identifies which main memory block is currently occupying that line. Without it, you can't tell if a hit is genuine.

Address Division — Step by Step

The Key Formulas

Word bits = log₂(block size in bytes)

Line/Set bits = log₂(lines) for direct — OR — log₂(lines/k) for k-way set-associative

Tag bits = Total address bits − Line bits − Word bits

Total address bits = log₂(main memory size in bytes)

★ Worked Example — 2025 Final Exam Style

Main memory = 2¹⁶ bytes (64KB), Block size = 8 bytes, Direct-mapped cache = 32 lines

Replacement Policies

When cache is full and a new block must come in, which line gets evicted? (Only applies to associative caches — direct mapped has no choice.)

LRU — Least Recently Used

Evict the line that was accessed longest ago. Best performance in practice — exploits temporal locality. But requires tracking access history = more hardware overhead.

FIFO — First In, First Out

Evict the oldest block regardless of when it was last used. Simpler but ignores usage patterns. Can evict a frequently used block just because it's been there longest.

Random

Pick a victim at random. Surprisingly competitive with LRU in practice, and trivially simple to implement.

// 07

Write Policies

When the CPU writes data — does it update main memory immediately or later?

Write-Through

Every write to cache is simultaneously written to main memory. Cache and memory always consistent. Simpler. But generates lots of memory traffic — slow.

Write-Back (Copy-Back)

Write only to cache; update main memory only when the block is evicted. A "dirty bit" flags modified lines. Faster, less bus traffic, but cache and memory temporarily inconsistent — problematic in multiprocessor systems.

Common exam follow-up: Why SRAM for cache, DRAM for main memory? SRAM is too expensive and large to use for GBs of RAM — but its speed is essential for cache. DRAM's density and cost make it practical for large main memory, despite being slower.

Magnetic Disk Performance

The Three Components of Disk Access Time

Seek Time (Ts) — time to move head to correct track

Rotational Latency (Tr) = (1/2) × (1/RPM × 60,000ms) — avg half rotation

Transfer Time (Tt) = (1/RPM × 60,000) / sectors per track × 1 sector

Total Access Time = Ts + Tr + Tt

★ Worked Example — From Your Exam Papers

Single platter disk: RPM=7200, Tracks=30,000, Sectors/track=600, Seek=1ms per 100 tracks

i. Average Seek Time Avg tracks traversed = 30,000/3 ≈ 10,000 tracks (For random access, avg = 1/3 of total tracks) Seek time = (10,000/100) × 1ms = 100ms ii. Average Rotational Latency Time for 1 revolution = 60,000ms / 7200 = 8.33ms Avg latency = 8.33 / 2 = 4.17ms iii. Transfer Time (1 sector) 1 revolution = 600 sectors → 1 sector = 8.33/600 = 0.0139ms iv. Total Average Access Time 100 + 4.17 + 0.0139 = ≈ 104.18ms

Hard vs Soft Errors

Hard Failures (Permanent)

A physical defect in the memory cell — caused by manufacturing faults, radiation damage, or component aging. The cell permanently gets stuck at 0 or 1. Cannot be corrected by re-writing. The cell must be remapped or the chip replaced.

Soft Errors (Transient)

A random, non-destructive bit flip — caused by cosmic rays, alpha particles, or power fluctuations. The underlying cell is fine; it just read the wrong value momentarily. Can be corrected by detecting and rewriting the correct data.

Error Correcting Codes (ECC/SEC) detect and fix soft errors. SEC (Single Error Correction) uses Hamming codes to identify and flip back the wrong bit.
