Why Number Systems?

Computers are fundamentally dumb machines that only understand two states — ON and OFF, 1 and 0. Every number you type, every image you see, every song you hear — it's all stored and processed as sequences of binary digits (bits). Understanding number systems is understanding the language of the machine.

We humans use base-10 (decimal) because we have 10 fingers. Computers use base-2 (binary) because transistors have 2 states. We use base-16 (hexadecimal) as a shorthand for binary because it's more compact. And base-8 (octal) shows up in older systems and Unix file permissions.

Exam focus: UNZA questions heavily test conversions between bases, 2's complement arithmetic, and BCD representation. Make sure you can do all of these by hand.

The Four Bases

BASE-10 · Decimal

Digits: 0-9. The default. Positional value is powers of 10.

Example: 347 = 3×10² + 4×10¹ + 7×10⁰
= 300 + 40 + 7 = 347
BASE-2 · Binary

Digits: 0, 1. The machine's native tongue. Positional value is powers of 2.

Example: 1011 = 1×2³ + 0×2² + 1×2¹ + 1×2⁰
= 8 + 0 + 2 + 1 = 11 (decimal)
BASE-8 · Octal

Digits: 0-7. Each octal digit = exactly 3 binary digits.

Example: 538 = 5×8¹ + 3×8⁰ = 40 + 3 = 43 (decimal)
Binary shortcut: 101 011 → 538
BASE-16 · Hexadecimal

Digits: 0-9, A-F. Each hex digit = exactly 4 binary digits. Very common in architecture (memory addresses, opcodes).

Example: 2F16 = 2×16¹ + 15×16⁰ = 32 + 15 = 47 (decimal)
A=10, B=11, C=12, D=13, E=14, F=15

Conversion Methods

Decimal → Binary (Divide by 2)

Keep dividing by 2, collect remainders bottom-to-top.

Convert 13 to binary: 13 ÷ 2 = 6 remainder 1 ← LSB 6 ÷ 2 = 3 remainder 0 3 ÷ 2 = 1 remainder 1 1 ÷ 2 = 0 remainder 1 ← MSB Read remainders ↑ = 11012
Binary → Decimal (Expand by Powers)

Multiply each bit by its positional value and sum.

Convert 101102 to decimal: Position: 4 3 2 1 0 Bit: 1 0 1 1 0 Value: 16 + 0 + 4 + 2 + 0 = 22
Binary ↔ Hex (Group by 4)

Group binary bits into groups of 4 from the right. Each group = 1 hex digit. Dead simple.

Convert 101111002 to hex: Group 4: 1011 1100 Convert: B C Result: BC16 Going back: B=1011, C=1100 → 10111100
Binary ↔ Octal (Group by 3)

Same idea but groups of 3.

Convert 1101012 to octal: Group 3: 110 101 Convert: 6 5 Result: 658

1's and 2's Complement

Why Complements?

Computers don't have a "subtract" circuit — they only add. So to compute A − B, they compute A + (complement of B). Clever, right?

1's Complement

Flip every bit. 0 → 1, 1 → 0.

1's complement of 0110 1001: Flip all bits → 1001 0110
2's Complement

The dominant method in modern computers. Two ways to get it:

METHOD 1: 1's complement + 1 Original: 0110 1001 1's comp: 1001 0110 + 1: 1001 0111 ← 2's complement METHOD 2 (Shortcut): Copy bits from right up to AND including first 1, then flip remaining bits. Original: 0110 1000 copy→↑ flip→↑ Result: 1001 1000
Subtraction using 2's Complement
Compute 15 − 6 using 8-bit binary: 15 = 0000 1111 6 = 0000 0110 2's comp of 6 = 1111 1010 Add: 0000 1111 + 1111 1010 ────────── 10000 1001 ↑ discard carry → result = 9 ✓

BCD & Other Codes

BCD (Binary Coded Decimal)

Each decimal digit is encoded separately as a 4-bit binary. BCD is NOT the same as converting a number to binary.

BCD of 39: 3 → 0011 9 → 1001 BCD = 0011 1001 Note: BCD 39 ≠ binary 39! Binary 39 = 0010 0111
Gray Code

Only ONE bit changes between consecutive values. Used in rotating encoders and error minimization — because if two bits flip at the same time in regular binary, you get a wrong value momentarily.

ASCII

7-bit code for text characters. 'A' = 65 = 0100 0001. Important because character data in memory is stored in ASCII (or its extensions like UTF-8).
